Jan, pogoda i wilgotność gleby (T-010 + T-037) są na main. Instrukcja dla orkiestratora (T-017).

## Zrobione
- `services/sources/meteo.source.ts`: `fetchMeteo(lat, lon, D, signal?)` zwraca `MeteoOutcome` = { series, source, fallback, confidencePenalty, limitations, sources, nasaSeries }; nigdy nie rzuca
- `series` (MeteoDay[]) jest zgodna z `DailyWeather` z kbw.ts: podaj wprost do `computeKbwWindows`
- `services/sources/era5land.ts`: `computeEra5LandSoilMoisture(series, D, thetaFc, thetaWp)` zwraca { soilMoisture (DM-015 bez agreement), status ok|missing }

## Potrzebuję od backend
- Dopisz `outcome.sources` do sources[] i `outcome.limitations` do limitations; odejmij `outcome.confidencePenalty` od pewności
- Gdy `fallback = false`: `computeEra5LandSoilMoisture(outcome.series, D, fieldCapacity, wiltingPoint)` z wyniku `computeSoilWater`; dodaj do sources[] wpis `era5land` ze statusem z wyniku; dopisz `agreement`
- Gdy `fallback = true`: `computeSoilMoisture(outcome.nasaSeries, D)` z nasaPower.source.ts, ustaw `fallback: true` i pola theta*M3 = null (funkcja ich nie zwraca)
- Uwaga: Open-Meteo dalej 429 z naszej sieci, więc na żywo przez chwilę będzie leciał zapas NASA POWER; testy tylko na fixtures
