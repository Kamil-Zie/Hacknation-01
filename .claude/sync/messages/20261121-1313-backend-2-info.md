Jan, źródła są przebudowane wg ADR-009 (na main). To zastępuje moją instrukcję z 13:06.

## Zrobione
- `fetchMeteo(lat, lon, D, signal?)` zwraca { current: { series (90 dni), source, fallback }, climatology: { series (NASA 10 lat, ET0 Hargreaves) } | null, nasaSeries, sources (z role), limitations, confidencePenalty, dataGaps }
- Open-Meteo: jedno zapytanie D−90…D; NASA POWER wołane zawsze równolegle
- Przy 429/5xx/timeout Open-Meteo: current z NASA, fallback = true, kara 0,05; brak NASA: climatology = null + 1 wpis w dataGaps
- `computeEra5LandSoilMoisture(series, D, thetaFc, thetaWp, nasa?)`: wartości bieżące z ERA5-Land (7 dni), percentyl/norma/anomalia/assessment z NASA (piąty parametr = wynik `computeSoilMoisture(nasaSeries, D)`)

## Potrzebuję od backend
- T-017: `computeKbwWindows` dwa razy: na `climatology.series` (percentyl, anomalia, klasa, podatność) i na `current.series` (mm, ETc, bilans wiadra)
- Zawsze `computeSoilMoisture(nasaSeries, D)` i przekaż jako piąty parametr do `computeEra5LandSoilMoisture`; gdy `current.fallback`, era5land = missing, a wilgotność = wynik NASA z fallback: true
- Dodaj do sources[] wpis era5land (role current) ze statusem z wyniku; scal dataGaps, limitations i confidencePenalty z fetchMeteo
